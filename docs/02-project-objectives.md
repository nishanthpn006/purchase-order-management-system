# Project Objectives

## Primary Objective

Develop a secure, scalable, and user-friendly Purchase Order Management System (POMS) that automates the complete purchase order lifecycle, from request creation to approval and tracking.

---

## Specific Objectives

### 1. User Authentication

- Allow users to securely log in using JWT authentication.
- Protect system resources from unauthorized access.

---

### 2. Role-Based Access Control

- Implement different permissions for Administrators, Procurement Managers, Purchase Officers, Finance Staff, and Employees.
- Restrict access based on user roles.

---

### 3. Vendor Management

- Maintain vendor information.
- Add, edit, search, and deactivate vendors.

---

### 4. Product Management

- Maintain a centralized catalog of products and services.
- Manage pricing and availability.

---

### 5. Purchase Request Management

- Allow employees to submit purchase requests.
- Track request status throughout its lifecycle.

---

### 6. Purchase Order Management

- Generate purchase orders from approved purchase requests.
- Track purchase order status.

---

### 7. Approval Workflow

- Support multi-level approval processes.
- Record approval history for auditing.

---

### 8. Dashboard

- Display system statistics and key metrics.
- Provide quick insights into procurement activities.

---

### 9. Reporting

- Generate procurement reports.
- Export reports when required.

---

### 10. Audit Logging

- Maintain logs of critical system activities.
- Improve accountability and traceability.

---

## Technical Objectives

- Follow Clean Code principles.
- Apply REST API best practices.
- Use mysql2 connection pooling with raw SQL queries.
- Store data in MySQL 8.
- Implement proper validation.
- Apply secure authentication.
- Maintain modular architecture.
- Produce professional documentation.
- Deploy the application to a cloud platform.

---

## Success Criteria

The project will be considered successful if it:

- Provides a complete purchase order workflow.
- Supports secure authentication and authorization.
- Demonstrates a scalable architecture.
- Maintains clean and readable code.
- Includes comprehensive documentation.
- Is deployed and accessible online.
